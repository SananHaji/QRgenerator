## 2. Set up a new computer

1. Clone: `git clone https://github.com/SananHaji/QRgenerator.git`
2. Install **JDK 21** and point Gradle at it. Android Studio's bundled JBR (Java 25) fails with "Unsupported class file major version 69".
   - Android Studio: Settings → Build → Gradle → Gradle JDK → JDK 21.
   - Terminal: `export JAVA_HOME=<path to JDK 21>`.
3. Android SDK 36 (Android Studio installs it on first sync). `local.properties` is generated by Android Studio.
4. **Copy the signing files by hand** (see §3). Without them debug builds work, release builds come out unsigned.
5. Build check: `./gradlew :app:assembleStoreDebug :app:testStoreDebugUnitTest`

## 3. Secrets that are NOT in git

The repository is **public**, so these must never be committed (`/signing/` is git-ignored):

- `signing/upload-keystore.jks` — Play **upload key** (Play App Signing holds the app signing key).
- `signing/keystore.properties` — keys `storeFile`, `storePassword`, `keyAlias`, `keyPassword`.

Move them via USB stick, AirDrop or a password manager, never via the repo or chat. Keep a backup copy. If the upload key is lost, Play Console → App integrity → "Request upload key reset" can replace it, but that takes days.

`app/google-services.json` is in git on purpose: it holds only public Firebase client ids.

## 4. Build variants

- `qrgenerator.hhm.enabled` in `gradle.properties` switches the HHM flavor on or off. With `false`, nothing HHM-related is compiled.
- Flavors: `store` (Play) and `hhm` (company build, `.hhm` suffix, `-hhm` version name).
- Debug builds send no Crashlytics/Analytics data (`firebaseCollectionEnabled=false`).

## 5. Release process

1. Bump `versionCode` and `versionName` in `app/build.gradle`.
2. Store bundle: `./gradlew :app:bundleStoreRelease` → `app/build/outputs/bundle/storeRelease/app-store-release.aab`.
3. HHM APK: `./gradlew :app:assembleHhmRelease` → `app/build/outputs/apk/hhm/release/`. Share it the usual way (Drive/Telegram); it installs over the previous HHM version because it uses the same key.
4. Play Console → Production → Create new release → upload the AAB → release notes (`<en-US>…</en-US>` tags per language) → Save → Publishing overview → Send for review.
5. Store listing edits: Store listings → Default store listing → edit → **Next → Save** (Save as draft alone does not reach the publishing overview).
6. A "native debug symbols" warning on upload is expected and does not block review.
